# bench-env — 計測用 AWS 環境（プロジェクト非依存）

HyperDiskUsage の性能計測に使っていた EC2 環境を、他のプロジェクトからも使える形に
切り出したもの。**このディレクトリは HyperDiskUsage に一切依存しない。** 別リポジトリへ
そのまま `git subtree split` できるよう、外部参照を持たない構成にしてある。

## 中心となる制約: インスタンスは共有しない

計測目的で 1 台を同時共有することはできない。理由は 4 つあり、うち 1 つは既に実害が出ている。

| 要因 | 何が起きるか |
|---|---|
| バースト型 CPU（T 系） | 隣のワークロードが CPU クレジットを消費し、計測値が劣化する |
| **バースト型 EBS 帯域（T 系）** | 同じ cold 実行が 0.495s → 0.81〜0.89s に変化した実害あり（`scripts/bench_du.sh` に記録） |
| ページキャッシュ | cold 計測に必要な `drop_caches` は**システム全体に効く**。他テナントの warm 計測を破壊する |
| 少ない vCPU | 並行負荷があるとスレッドスケーリングの計測が無意味になる |

したがって本環境の方針は **「インスタンスではなく環境定義を共有する」**。
1 回の計測 = 1 インスタンス。使い終わったら破棄する。排他制御は「専有インスタンス」
そのものが担うので、ロック機構は要らない。

## インスタンス型を T 系から変えた理由

| | 旧 | 新（既定） |
|---|---|---|
| 型 | `t3.large` | `m5d.large` |
| vCPU / RAM | 2 / 8 GiB | 2 / 8 GiB（**据え置き**） |
| CPU 性能 | バースト（クレジット制） | 固定 |
| EBS 帯域 | バースト | 固定 |
| ストレージ | EBS gp3 | **ローカル NVMe**（インスタンスストア） |

vCPU と RAM を据え置いたのは、**過去の計測値と形が比較可能なまま**にするため。
変えたのは非決定性の原因だけ。

ローカル NVMe にしたのは 2 つの理由による。

1. EBS のネットワーク経由という要素を計測から外せる
2. **`mkfs` を自由に打てる**ので xfs / ext4 / btrfs を並べて置ける（Linux 固有機能の検証に必要）

スレッドスケーリングを測りたい場合は `--instance-type m5d.2xlarge`（8 vCPU）を指定する。
**ただし 2 vCPU 時代の数値とは直接比較できない**ので、比較対象も同じ型で測り直すこと。

### Spot インスタンスは使わない

中断が計測の最中に起きると、その run は捨てるしかない。中断されなかった run だけが
残ると、結果に生存バイアスがかかる。計測用途では on-demand を使う。

## 使い方

```bash
# 1. 起動（専有インスタンスが 1 台立つ）
./aws/launch.sh --project myproject --ttl 120

# 2. 出力された ssh コマンドで入る。/mnt/xfs /mnt/ext4 /mnt/btrfs が用意済み
#    計測規約は protocol/lib.sh を source して使う

# 3. 破棄（TTL 超過でも自動で terminate される）
./aws/terminate.sh --project myproject
```

`--ttl` は分単位のハードリミット。指定を忘れても既定 180 分で必ず落ちる。
**計測中に落ちて困るより、消し忘れて課金が続くほうが困る**という判断。

## 計測規約（protocol/lib.sh）

HyperDiskUsage で「一度は破った」ルールを、コメントではなく**コードで強制**している。
他プロジェクトでもそのまま使えるよう、比較対象のコマンドを引数で受け取る汎用形にした。

| ルール | 根拠 |
|---|---|
| warm は最小値、**cold は中央値** | cold の最小値はバースト状態を定常状態として報告してしまう |
| cold は burn-in してから交互実行 | 2 つのツールに同じ定常状態を見せるため |
| 環境メタデータを必ず記録 | 後から「その数値がどの条件のものか」を復元できないと意味がない |

`protocol/verify.sh` は計測前に環境が計測可能な状態かを検査し、駄目なら**中断する**
（警告は読み飛ばされるため）。

## コスト

`--project` タグでコスト配分が追える。プロジェクト別の内訳は Cost Explorer の
タグフィルタで見る。正確な単価は AWS の料金ページを参照すること
（型とリージョンで変わるため、ここには書かない）。

TTL による自動 terminate があるので、消し忘れによる青天井の課金は起きない。

## 未検証の項目

このディレクトリのスクリプトは、**AWS 認証情報が有効なセッションでの実行検証をまだ
していない**（作成時のセッションでは `sts get-caller-identity` が
`InvalidClientTokenId` で失敗した）。以下は初回実行時に確認が要る。

- `launch.sh` の AMI 検索が意図した Amazon Linux 2023 を引くか
- インスタンスストアのデバイス名（`/dev/nvme1n1`）が `m5d.large` で正しいか
- cloud-init の完了検知が機能するか
- `m5d.large` のインスタンスストア容量が、対象ツリーを置くのに足りるか
